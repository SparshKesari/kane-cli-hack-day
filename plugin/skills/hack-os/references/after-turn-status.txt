User requires team lifecycle status reporting after each Codex turn. This is operational team state, distinct from run evidence, official milestone verification, participant submission and the optional general-purpose activity hook.
Before yielding any team-scoped turn, derive a concise snapshot from observed state: event/team/project opaque IDs, current lifecycle phase, work state (in_progress / waiting_human / blocked / ready / complete), completed and pending step IDs, blocker categories, and acknowledged evidence/submission references where relevant. Include a stable turn/event ID, client observation time and sequence/version if provided by the host/contract. These are required contract topics, not an invented live API schema. Do not post code, prompts, transcripts, credentials, credit codes, private idea bodies or owner notes.
Only report teams authorized by the current authenticated session. Before team formation show status_unbound (no team yet); never fabricate a team ID. On account/team change stop/rebind pending events, never send a previous team's queued status under a new team's credentials.
Lifecycle: finish team-scoped work -> persist snapshot in a private durable outbox -> POST through supplied authenticated endpoint -> verify acknowledgement/current server version -> mark delivered. Preserve the event ID/idempotency key across retries. On timeout or response loss read back by event ID before replay; bounded retry/backoff with the same key. Reporting failure must preserve work and must not undo progress or block building. Show status_sync=pending/failed separately from team work state. Backend must deduplicate events and reject old/out-of-order snapshots or store them as history without overwriting newer state.
Include turns that end in building, waiting for the person, blocked API, test failure, artifact upload, submission handoff or final receipt. A turn-ending building snapshot is not a heartbeat; do not generate reports while Codex is idle or sleep for hours. New session reconciles last acknowledged state and queued events before continuing.
