No prior website signup is required by the requested flow. Installer starts prerequisite checking/installation, skill discovery and Codex handoff. Skill then guides account creation, secure browser identity proof, session pairing, profile/photo-or-skip and team APIs. Installer cannot itself silently start an authenticated Codex session; participant completes required browser grants and starts/continues Codex with $hack-os. In a no-TTY shell, do not interpret skipped installs as successful setup.

Inspected branch src/server/flow.ts currently orders /register -> photo/skip -> team choice -> team lock -> /activate (entitlements) -> /setup -> hub. This is a migration gap with requested installer-first flow. Signup submitProfile is a browser server action; /api/v1/profile/check only validates social handles and is NOT account creation. Authenticated participant_update_profile is NOT unauthenticated signup. Supply a pre-auth registration/browser-session handoff API before claiming signup can be completed entirely by API. Existing-account recovery requires proof; never claim an email-only account.
Passwords, one-time codes, Codex credit codes and OAuth secrets stay in secure human/browser flows. Skill orchestrates all steps, asking only missing nonsecret profile values. Branch profile currently requires GitHub/X/LinkedIn fields and a password (8+ characters); follow current validated schema rather than older optional-field assumptions.

LONG BUILD PHASE
After team, activation readiness and idea, enter building. Save nonsecret event/participant/team/project IDs, workspace, known repo SHA, completed checks and pending contracts. Record {id:"build",status:"building",reason:"Participant building; resume when ready"} in the checklist.
Building can last hours. End the onboarding turn with: “You're ready to build. Use Kane as you work. Say '$hack-os, ready to submit' when you're ready.” End the turn rather than run a long sleep or create a recurring task. No constant polling. No elapsed-time rule can mark building done. When requested to test/fix/help, work through the official Kane skill and preserve building state. A new session reads cache then canonical state, without repeating signup/team grants. On ready-to-submit mark the build phase ready based on the participant request; artifact validation and approval remain separate.
Backend work while participants build: persist real opted-in run metadata, process deduped telemetry/evidence validation if available, mentor tickets, server event phases/deadlines and operational inventory/provider health. These services run independently of a continuously active Codex turn. Hooks remain optional; never claim telemetry is live without source receipts.

EVIDENCE IS A SEPARATE PUBLIC BUCKET PATH
User explicitly requires evidence to be pushed separately to a public bucket. Its upload endpoint/signed-upload contract and public base URL WILL BE PROVIDED LATER; do not reuse the existing private upload endpoint and label it public.
Prepare only participant-approved public-safe evidence exports; preserve original local evidence, redact credentials/private data, compute SHA256, map each object to team/project/run/commit. Request scoped upload authorization, upload directly to the supplied bucket endpoint, acknowledge completion, verify checksum/size and public-read URL, then persist object/evidence receipt. Deduplicate by digest; resume per-object, retry without duplicating. Bucket object existence does not prove a passing run or backend milestone.
Public bucket failure: retain local files and manifest with upload=pending. Event API outage: upload may proceed independently if its authorization endpoint still works; API linking/page creation remains pending. Never fabricate an upload, receipt or public URL. Do not put reusable storage credentials into the skill.
Required future contract: allowed public origin, authorization method, upload URL issuance and expiry/refresh, method/headers/MIME/max-size rules, completion/readback, stable object ID/public URL, digest verification, duplicate/resume semantics and error shapes. No provider is assumed.
Existing source src/app/api/v1/kane/evidence routes store PRIVATE Blob: direct <=4 MB, signed upload <=50 MB with validation/quarantine/deduplication. That is an existing distinct integration; it does not satisfy the new public bucket requirement.
